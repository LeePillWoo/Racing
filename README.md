# APEX — Formula Circuit

Three.js + Rapier 기반의 브라우저 포뮬러 레이싱 게임입니다. 기존 사막 스포츠카 프로젝트를 밝은 잔디 서킷으로 변경했습니다.

## 실행
- Node.js 24 이상
- `npm install`
- `npm run dev`: 개발 서버. 브라우저에서 http://127.0.0.1:5173 으로 엽니다. VS Code의 Go Live(Live Server)나 index.html 직접 열기로는 화면이 뜨지 않습니다. TypeScript와 `import` 구문을 변환해 줄 Vite가 필요합니다.
- `npm run build`: 타입 검사 및 dist 빌드
- `npm test`: 실제 Rapier 시뮬레이션을 포함한 50개 회귀 검사
- `npm run test:browser`: 개발 서버(127.0.0.1:5173)가 켜진 상태에서 실행. Playwright 및 Chromium이 필요합니다. 설치된 playwright 패키지 또는 Windows의 기존 Playwright 브라우저 연결을 사용합니다.

## 코스
시작 화면에서 세 개의 코스 중 하나를 고릅니다. 코스마다 도로 폭, 랩 수, 배경이 다릅니다.

| 코스 | 길이 | 랩 | 특징 |
| --- | --- | --- | --- |
| APEX GRAND PRIX | 1.30 km | 3 | 관중석을 낀 정통 그랑프리. 긴 직선과 고속 코너. |
| SWITCHBACK PARK | 2.84 km | 2 | 모래 고원을 가로지르는 연속 헤어핀, 호수를 낀 롱 스트레이트. |
| INFINITY DRIFT | 2.03 km | 3 | 스스로를 한 번 가로지르는 8자 드리프트 아레나. 검은 패독, 파랑 커브, 타이어 월. |

코스 정의는 `src/track/TrackCatalog.ts` 한 곳에 모여 있습니다. 제어점, 도로 폭, 랩 수와 하늘·지면·커브 색·구조물까지 같은 객체에 들어갑니다.
8자 코스처럼 스스로 교차하는 레이아웃은 교차 구간의 커브와 방호벽을 자동으로 제거해 길을 막지 않습니다.

## 차량
시작 화면에서 코스와 차량을 각각 고릅니다. 차체는 네 종류이고, 도색 조합까지 여덟 대입니다.

| 차체 | 차량 | 생김새 |
| --- | --- | --- |
| formula | APEX FW-01, SILVER ARROW | 오픈휠 단좌식. 헬멧과 헤일로가 드러납니다. |
| gt | VENOM GT, MIDNIGHT GT | 지붕과 펜더가 있는 클로즈드 콕핏 GT. |
| hyper | SCARLET X, COBALT X | 낮게 깔린 미드십 웨지. 캐노피와 대형 리어윙. |
| muscle | HORNET V8, EMBER V8 | 보닛 위로 엔진이 솟은 머슬카. 사이드 파이프. |

**성능은 전부 같습니다.** 섀시, 변속기, 타이어를 공유하므로 고르는 기준은 취향과 12대 사이에서 내 차를 알아보는 것뿐입니다.
AI는 플레이어가 고른 차를 빼고 나머지를 돌아가며 받으므로, 그리드가 같은 차 열두 대가 되지 않습니다.
차량 정의는 `src/vehicle/CarCatalog.ts`, 차체 형상은 `src/vehicle/CarMesh.ts`에 있습니다.

### 재질
부품마다가 아니라 **표면 종류마다** 재질을 하나씩 씁니다. 차체는 재질 단위로 배칭되므로 재질 하나가 곧 드로우콜 하나입니다.

| 재질 | 러프니스 | 쓰임 |
| --- | --- | --- |
| paint / accent | 0.44 + 클리어코트 1.0 | 도장 패널. 안료층은 색을 지키고 위에 덮인 클리어코트가 반짝입니다. |
| chrome | 0.05, 메탈 1.0 | 범퍼, 배기, 슈퍼차저. |
| glass | 0.04, 메탈 0.95 | 유리와 바이저. |
| metal | 0.28, 메탈 0.95 | 서스펜션 암, 브레이크 디스크, 휠 스포크. |
| carbon | 0.92 | 카본과 성형 플라스틱. 매트. |
| rubber | 0.99, 메탈 0 | 타이어. 가장 매트합니다. |

반사가 보이려면 비출 것이 있어야 합니다. 로딩 때 그 코스의 하늘을 PMREM으로 한 번 구워 `scene.environment`에 넣습니다.
프로브 안에는 하늘보다 훨씬 밝은 태양 원반을 같이 넣습니다. 이게 없으면 반사가 매끈한 그라데이션이라 평평한 면은 단색 하나만 비추고, 결국 매트해 보입니다.
각진 상자는 면마다 단색을 비추므로 도장 패널은 모서리를 넉넉히 굴렸습니다. 굴린 모서리가 반사를 훑고 지나가면서 광택으로 읽힙니다.
블룸은 임계값을 2.4로 잡아 햇빛만으로는 절대 안 터지게 했습니다. 클리어코트에 비친 태양, 크롬, 유리, 배기 화염만 번집니다.

## 모바일과 태블릿
화면비로 대응합니다. 가로 전용이 아니고, 세로로 들어도 가로로 눕혀도 태블릿에서도 각각 배치가 맞습니다.

**조향은 왼쪽 화면을 끌어서 합니다.** 왼쪽 어디든 누르면 그 자리에 노브가 뜨고, 손가락이 처음 닿은 곳에서 얼마나 움직였는지에 비례해 조향합니다.
화면 가운데 고정된 스틱을 더듬어 찾을 필요가 없습니다. 최대 각도를 넘겨 더 끌면 기준점이 손가락을 따라오므로, 손을 떼지 않고 코너 중간에 다시 중립을 잡을 수 있습니다.
이동 거리는 화면 너비의 16%이고 64~150px로 제한합니다. 태블릿에서 손톱만큼만 움직여도 풀락이 되거나, 폰에서 화면을 다 쓸어야 하는 일이 없도록 한 값입니다.

오른쪽에는 GO, BRAKE, DRIFT, BOOST 네 개를 둡니다. 버튼 크기는 `clamp(56px, 14vmin, 92px)`이고 GO는 그 1.32배입니다. 노치와 홈 인디케이터는 `env(safe-area-inset-*)`로 피합니다.

HUD 패널은 각자 좌표를 갖지 않고 **화면 가장자리에 붙인 세 개의 흐름 컨테이너** 안에서 흐릅니다.
세로로 긴 데스크톱 창 기준의 고정 좌표였을 때는 가로로 누운 폰에서 미니맵이 랩타임 위에, 순위표가 속도계를 뚫고 지나갔습니다. 컨테이너는 자기 자신과 겹칠 수 없으니 그 문제가 통째로 사라지고, 크기만 조절하면 됩니다.

높이 520px 이하(가로로 누운 폰)에서는 왼쪽 열이 상단 가로줄로 눕고, 미니맵과 속도계는 양쪽 엄지가 닿지 않는 화면 가운데 아래로 내려갑니다.
순위표는 실제로 남는 높이를 계산해 줄 수를 줄이되, 선두 몇 명과 **내 순위는 항상** 남기고 사이는 `···`로 표시합니다.

## 충돌 파손
일정 속도 이하의 접촉은 무시합니다. 그보다 세게 부딪히면 부딪힌 위치에 따라 부품이 상합니다. 플레이어와 AI 모두 동일하게 적용됩니다.

**파손은 2단계입니다.**

| 단계 | 상태 | 보이는 것 | 접지력 |
| --- | --- | --- | --- |
| 1차 | 헐거워짐 | 바퀴가 캠버 먹고 주저앉아 덜덜 떨립니다. 윙은 한쪽으로 처져 끌립니다. | 바퀴 55%, 윙 95% |
| 2차 | 떨어짐 | 부품이 튕겨 나가 바닥을 구릅니다. | 바퀴 9%, 윙 88% |

**한 번의 충돌로는 절대 부품이 떨어지지 않습니다.** 단일 충돌 데미지 상한(`maxSeverity`)을 파손 임계값보다 낮게 잡아서, 아무리 세게 받아도 1차까지만 갑니다.
부스터를 켜고 받으면 1.8배로 아프지만, 그 배율을 곱한 뒤에 상한을 적용하므로 이 규칙은 깨지지 않습니다.
덕분에 한 번의 실수로 레이스가 끝나지 않고, 떨어지기 전에 항상 경고 단계가 있습니다.

- **정면으로 벽을 받으면** 앞쪽 두 코너가 충격을 나눠 가집니다. 한 번이면 프런트 윙과 앞바퀴가 헐거워집니다.
- **한쪽 코너로 비스듬히 긁으면** 충격이 그 코너에 몰립니다. 같은 자리를 두 번 받으면 그 바퀴가 빠집니다.
- 떨어진 부품은 바닥에 굴러다니다 사라집니다. 주행을 방해하는 충돌체는 만들지 않습니다.
- `R` 복귀를 누르면 차가 원래대로 복구됩니다. 휘어진 윙도 펴집니다.

좌측 데미지 패널이 단계를 구분해 보여줍니다. 성한 칸은 초록, 금 간 칸은 노랑, **헐거운 칸은 주황으로 떨리고**, 떨어진 칸은 빈 빨간 테두리가 됩니다.

수치는 `src/vehicle/Damage.ts`의 `DEFAULT_DAMAGE` 한 곳에 있습니다.

## 조작
WASD / 방향키: 가속·브레이크·후진·조향. Space: 드리프트(핸드브레이크). Shift: 부스터(자동 충전, 드리프트 성공 시 추가 충전). R: 트랙 복귀 및 차량 수리. C: 카메라 거리. Esc: 일시정지 후 [메인 화면으로] 버튼으로 코스 선택으로 돌아갑니다.
터치 장치에서는 왼쪽 드래그 조향 패드와 오른쪽 주행 버튼이 나타납니다. 다른 창으로 이동하면 자동으로 일시정지됩니다.

## 공개 사이트 배포
공개 주소: https://leepillwoo.github.io/Racing/

`main`에 push하면 `.github/workflows/deploy-pages.yml`이 의존성 설치, 회귀 검사, 빌드를 실행한 뒤 `dist/`를 GitHub Pages에 배포합니다. 저장소 Settings → Pages의 Source는 **GitHub Actions**를 사용합니다.
GitHub Actions에서 배포 성공을 확인한 뒤 공개 주소를 새로고침하세요. 로컬 파일 수정만으로 공개 사이트가 갱신되지는 않습니다.
이전 `gh-pages` 브랜치는 과거 배포 기록이며, 현재 공개 버전의 배포 소스로 사용하지 않습니다.

## 변경 사항
- 12대의 오픈휠 차량, 전후 윙·서스펜션·콕핏·헬멧. 플레이어는 파랑/노랑, 12번 그리드에서 출발합니다.
- 코스 3종과 차량 8종, 시작 화면에서 각각 선택. 레이아웃 썸네일과 차량 실루엣 표시.
- 차체 폴리곤을 약 2배로 올리고 표면 종류별로 재질을 분리. 하늘 반사 프로브와 하이라이트 전용 블룸 추가.
- 모바일·태블릿 대응: 왼쪽 드래그 아날로그 조향, 큰 주행 버튼, 화면비에 따라 재배치되는 HUD.
- 인게임 좌측 데미지 패널: 네 코너와 앞뒤 윙 상태를 표시하고, 떨어져 나간 부품은 비워서 보여줍니다.
- 충돌 파손: 속도·각도·부스터에 따라 윙과 바퀴가 떨어져 나가고 파편이 남습니다. 일시정지에서 메인 화면 복귀.
- 약 1.30 km, 3랩의 잔디 서킷. 관중석, 안전 펜스와 충돌벽, 열기구, 출발 그리드와 결승선.
- 낮은 후방 카메라, 밝은 주간 조명, 새 시작 화면과 HUD. 차량 고정 부품은 재질별로 병합합니다.
- 약 0.6 m/s 이후 후진 동력이 끊기던 조건과 Rapier 사용자 토크 누적 수정.
- 출발 위치를 반영한 순위, 공통 결승선 기준 랩 계산, 같은 프레임 내 결승 통과 시각 비교.
- 트랙 좌우 벡터와 도로 루프 연결, 연속 투영 보정. 트랙 밖 이동·큰 위치 점프로 진행 거리를 얻지 못합니다.
- 물리 시간 누적 상한, 실제 시뮬레이션 시간에 맞는 랩 타이머, 리셋 상태 정리, 키 반복/포커스 해제 처리.
- 시작 전 정지 그리드 미리보기, 카운트다운, 일시정지 및 터치 조작.

## 검증과 범위
회귀 검사에는 실제 차량의 가속·조향·후진·접지·리셋, 랩/순위, AI 한 바퀴 완주, 안전벽 충돌을 포함합니다.
등록된 모든 코스에 대해 최소 코너 반경, 방호벽이 자기 도로를 막지 않는지, AI가 실제로 한 바퀴를 도는지 검사합니다.
파손은 실제 차량을 벽에 충돌시켜 검사합니다. 한 번 받으면 휘기만 하고, 같은 자리를 반복해 받아야 떨어지고, 저속 접촉과 정상 주행은 무손상이어야 합니다.
속도·각도·부스터를 바꿔가며 단일 충돌로는 어떤 부품도 떨어지지 않는다는 규칙 자체를 검사합니다.
브라우저 검사는 차량을 골라 출발한 뒤 그 차가 실제로 나오는지, 그리드에 차체가 섞여 있는지, 데미지 패널이 맞게 갱신되는지, 반사 프로브가 걸렸는지 확인합니다.
회귀 검사는 도장이 클리어코트를 가졌는지, 고무와 카본이 매트인지, 크롬과 유리가 연마 금속인지를 수치로 확인합니다.
브라우저 검사는 로딩·가속·후진·일시정지·카메라·가로/세로 화면을 확인하고 artifacts/에 화면을 저장합니다.
터치 검사는 한 엄지로 GO를 누른 채 다른 엄지로 조향 패드를 끌어, 짧게 끌면 부분 입력이고 끝까지 끌면 풀락인지 확인합니다. 주행 중 HUD 컨테이너끼리 겹치거나 화면 밖으로 나가지 않는지도 좌표로 검사합니다.
그래픽은 외부 모델/이미지 다운로드 없이 생성하는 실시간 3D 아케이드 스타일입니다. 실사 에셋과 사운드는 포함하지 않습니다.
Rapier WASM이 포함되어 배포 번들이 큽니다. 실제 모바일 기기와 다양한 GPU에서의 성능은 별도 확인이 필요합니다.
개발 모드의 window.__racing은 자동 검증용이며 배포 빌드에서는 제거됩니다.
